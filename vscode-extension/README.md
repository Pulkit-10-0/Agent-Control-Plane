# Agent Control Plane - VS Code Extension

A time-travel debugger for AI agents. Reconstructs agent cognition from deterministic execution traces, providing visual inspection, step-by-step replay, LangGraph visualization, state diffing, root-cause analysis, and counterfactual simulation.

## Supported Trace Formats

The extension accepts two trace formats:

### 1. SDK Run Folder (recommended)

Generated by the ACP Python SDK. Structure:

```
traces/
  run_<uuid>/
    meta.json          # Run metadata
    steps.jsonl        # One JSON object per line, one per step
    snapshots/         # Optional: step_<id>.json state snapshots
    diffs/             # Optional: step_<id>.diff.json state diffs
    tools/             # Optional: step_<id>.stdout, step_<id>.stderr
```

**meta.json** fields:

| Field           | Type     | Description                            |
|-----------------|----------|----------------------------------------|
| `run_id`        | string   | UUID identifying this run              |
| `agent_version` | string   | Version of the agent that produced it  |
| `llm`           | string   | Model name (e.g. `gpt-4o`)            |
| `temperature`   | number   | Sampling temperature                   |
| `tools`         | string[] | List of tool names available           |
| `seed`          | number   | Random seed for reproducibility        |
| `created_at`    | string   | ISO 8601 timestamp                     |

**steps.jsonl** fields (per line):

| Field       | Type   | Description                                    |
|-------------|--------|------------------------------------------------|
| `step_id`   | number | Sequential step identifier                     |
| `timestamp` | number | Unix epoch seconds                             |
| `phase`     | string | `reason`, `tool`, `observe`, `memory`, `retry`, `terminate` |
| `input`     | object | Step input payload                             |
| `output`    | object | Step output payload                            |
| `state_ref` | string | Path to snapshot file (e.g. `snapshots/step_1.json`) |
| `diff_ref`  | string | Path to diff file (optional)                   |
| `status`    | string | `ok`, `error`, or `retry`                      |
| `duration`  | number | Execution time in milliseconds (optional)      |

### 2. Legacy Single-JSON

A single JSON file containing the full trace:

```json
{
  "traceId": "trace_abc123",
  "agentId": "my-agent",
  "status": "completed",
  "startTime": "2024-01-01T00:00:00Z",
  "steps": [
    {
      "stepNumber": 1,
      "stepType": "llm",
      "timestamp": "...",
      "input": {},
      "output": {},
      "stateSnapshot": {},
      "duration": 150
    }
  ],
  "metadata": {
    "agentVersion": "1.0.0",
    "toolsUsed": ["search", "write"],
    "totalLLMCalls": 5,
    "totalToolCalls": 3
  }
}
```

Step type values: `start`, `llm`, `tool`, `decision`, `error`, `end`.

## Features

### Trace Browser

**Command:** `ACP: Open Trace` (`acp.openTrace`)

Discovers traces automatically from the workspace. The sidebar **Traces** view shows:
- SDK run folders (`run_*` directories containing `meta.json`)
- Legacy JSON trace files (`traces/*.json`)

Click any item to load it. The extension auto-detects the format.

**Command:** `ACP: Open SDK Run Folder` (`acp.openRun`)

Opens a folder picker to select an SDK run directory directly.

---

### Replay Controller

**Commands:**
| Command                 | ID                  | Description                    |
|-------------------------|---------------------|--------------------------------|
| Replay - Play           | `acp.replay.play`   | Auto-advance steps (1s/step)   |
| Replay - Pause          | `acp.replay.pause`  | Pause auto-play                |
| Replay - Stop           | `acp.replay.stop`   | Stop and reset to step 0       |
| Replay - Next Step      | `acp.replay.next`   | Advance one step               |
| Replay - Previous Step  | `acp.replay.prev`   | Go back one step               |
| Replay - Jump to Start  | `acp.replay.start`  | Jump to first step             |
| Replay - Jump to End    | `acp.replay.end`    | Jump to last step              |
| Replay - Jump to Step   | `acp.replay.jump`   | Enter a step number to jump to |
| Replay - Search Steps   | `acp.replay.search` | Text search across step I/O    |

The replay panel opens in the editor (Column Two) showing:
- **Input:** Step replay controls (play, pause, step forward/backward)
- **Output:** Progress bar, current step input/output/timestamp, clickable step list

All replay actions sync with the sidebar providers (Timeline, State Inspector, Diff Viewer) and the LangGraph panel.

---

### LangGraph Visualization

**Command:** `ACP: Show Execution Graph` (`acp.showLangGraph`)

Uses the real `@langchain/langgraph` library (`StateGraph`, `Annotation`, `START`, `END`) to model agent execution as a compiled graph.

**Input:** The currently loaded trace (either format).

**Output:** A panel with three tabs:
- **Graph:** SVG node-edge diagram showing execution flow. Nodes are color-coded by type (LLM=green, tool=blue, error=red). Click a node to inspect its steps.
- **Nodes:** Flat list of all graph nodes with execution counts and durations.
- **Mermaid:** Raw Mermaid markup generated by `drawMermaid()` from the compiled `StateGraph`.

Toggle **In/Out/Both** to control what data is shown in the detail pane.

The graph highlights the current replay step in real-time.

---

### Timeline (Sidebar)

**View:** `acp.timelinePanel` (in the Agent Control Plane activity bar)

Phase-colored step list with keyboard navigation (Arrow Up/Down).

**Input:** Loaded SDK run via `RunContext`.

**Output:** Interactive step list showing:
- Step ID, phase badge (color-coded: reason=green, tool=blue, observe=purple, memory=orange, retry=orange-bordered)
- Status indicator (OK/ERR/RETRY)
- Step summary text
- Truncation warning banner if the run was cut short

Click a step to navigate to it. Previous/Next buttons for sequential navigation.

---

### State Inspector (Sidebar)

**View:** `acp.stateInspector` (in the Agent Control Plane activity bar)

**Input:** Currently selected step from `RunContext`.

**Output:** Four sections:
- **Step Input:** JSON-formatted input payload
- **Step Output:** JSON-formatted output payload
- **Memory Snapshot:** Loaded from `snapshots/step_<id>.json` (lazy-loaded)
- **Tool Logs:** stdout/stderr from `tools/step_<id>.stdout` / `.stderr`
- **Metrics:** Context token count, memory entry count

All values pass through `SecretRedactor` which masks:
- OpenAI keys (`sk-...`)
- GitHub tokens (`ghp_...`)
- JWTs (`eyJ...`)
- Slack tokens (`xox[baprs]-...`)
- Any object key matching `/key|token|secret|password|auth/i`

---

### Diff Viewer (Sidebar)

**View:** `acp.diffViewer` (in the Agent Control Plane activity bar)

**Input:** Currently selected step.

**Output:** Two buttons:
- **Diff Input/Prompt:** Opens VS Code's native diff editor comparing step N-1 input with step N input.
- **Diff Memory:** Opens VS Code's native diff editor comparing step N-1 memory snapshot with step N memory snapshot.

Uses the `acp-diff:` URI scheme backed by `DiffContentProvider`.

---

### Hierarchy Tree (Sidebar)

**View:** `acp.hierarchyView` (in the Agent Control Plane activity bar)

**Input:** Loaded SDK run.

**Output:** Tree view with grouping modes:

| Command                    | ID                           | Grouping                  |
|----------------------------|------------------------------|---------------------------|
| Group by Phase             | `acp.hierarchy.groupByPhase` | Groups steps by phase     |
| Group by Status            | `acp.hierarchy.groupByStatus`| Groups steps by status    |
| Flat List (No Grouping)    | `acp.hierarchy.groupByNone`  | Flat sequential list      |

Click any step item to jump to it via `acp.jumpToStep`.

Grouping commands are also available in the view's title bar.

---

### Step Navigation

**Command:** `ACP: Jump to Step` (`acp.jumpToStep`)

**Input:** Step ID (number).

**Output:** Navigates `RunContext` to the specified step, updating all sidebar providers and the replay panel.

---

### Jump to First Failure

**Command:** `ACP: Jump to First Failure` (`acp.openFailure`)

**Input:** Currently loaded SDK run.

**Output:** Finds the first step with `status === "error"` and navigates to it. Shows an informational message if no failures are found.

---

### Diagnosis Report

**Command:** `ACP: Generate Diagnosis Report` (`acp.generateReport`)

**Input:** Currently loaded SDK run.

**Output:** HTML report panel with:
- **Invariant Checks:**
  - Retry Ceiling: FAIL if retry rate > 50% of all steps
  - Tool Order: Checks for write-before-read violations
- **Root Cause Analysis:**
  - Identifies the first error step
  - Builds a causal chain of the 3 preceding steps
  - Reports confidence level (default 0.8)
  - Describes likely failure cause

---

### Run Comparison

**Command:** `ACP: Compare Two Runs` (`acp.compareRun`)

**Input:** Currently loaded SDK run (base) + a second run folder selected via folder picker.

**Output:** Side-by-side comparison panel showing:
- Delta duration and delta step count
- Divergence point detection (first step where input/output differs)
- Step alignment table with match types:
  - **Exact:** Same phase and same input
  - **Phase:** Same phase, different input
  - **Mismatch:** Different phase entirely
- Color-coded rows (green = exact, orange = phase match, red = mismatch)

---

### Counterfactual Simulation

**Command:** `ACP: Create Counterfactual Simulation` (`acp.counterfactual`)

**Input:**
1. Currently loaded SDK run
2. Step ID to branch from (prompted)
3. New input as JSON (prompted)

**Output:**
- Creates a new `run_<timestamp>_sim/` directory alongside the original run
- Copies `meta.json` with updated tags (`simulation`, `from:<original-run-id>`)
- Keeps all steps before the branch point unchanged
- Applies the modified input to the branch step
- Marks the branch step with `status: "retry"` as divergence indicator
- Creates empty `snapshots/`, `diffs/`, `tools/` directories
- Prompts to open the simulation as a new run

---

### Analysis Engine (Internal)

**Module:** `src/engines/AnalysisEngine.ts`

Semantic labeling system:
- `retry-loop`: Consecutive retry-status steps
- `exploration`: Tool calls containing `search`, `ls`, or `read`
- `commitment`: Tool calls containing `write` or `edit`

---

## Architecture

```
src/
  extension.ts                 # Entry point, wires all providers and commands
  commands/
    CommandHandlers.ts          # SDK-format command implementations
  data/
    DataTypes.ts                # SDK trace interfaces (RunMeta, AgentStep, etc.)
    RunContext.ts               # Singleton state manager with event emitters
    RunLoader.ts                # Loads meta.json + steps.jsonl, lazy snapshots
  engines/
    AnalysisEngine.ts           # Semantic labels, invariants, root cause
    ComparisonEngine.ts         # Step alignment, divergence, metric diffs
    CounterfactualEngine.ts     # Fork+simulate from any step
  langgraph/
    LangGraphBuilder.ts         # Real @langchain/langgraph StateGraph builder
  providers/
    DiffContentProvider.ts      # acp-diff: URI scheme for VS Code diff editor
  ui/
    LangGraphProvider.ts        # WebviewPanel: SVG graph, Mermaid, node list
    TimelineProvider.ts         # WebviewViewProvider: phase-colored timeline
    StateInspectorProvider.ts   # WebviewViewProvider: step I/O + memory + logs
    DiffViewProvider.ts         # WebviewViewProvider: diff buttons
    HierarchyProvider.ts        # TreeDataProvider: grouped step tree
    ComparisonViewProvider.ts   # WebviewPanel: side-by-side run comparison
  utils/
    SecretRedactor.ts           # Regex-based credential masking
```

### Data Flow

1. User opens a trace (JSON or SDK folder) via command palette or sidebar
2. `extension.ts` detects the format:
   - SDK folder: loads via `RunContext.loadRun()` -> `RunLoader`
   - Legacy JSON: parses directly into `LegacyTrace`
3. SDK runs fire `RunContext.onDidRunChange` which:
   - Converts to legacy format for the replay panel
   - Normalizes to `TraceData` for `LangGraphBuilder`
   - Notifies all sidebar providers (Timeline, State Inspector, Diff Viewer, Hierarchy)
4. Replay controller steps sync back to `RunContext.setStep()`, keeping all views in lockstep
5. `LangGraphBuilder` creates a real `StateGraph`, compiles it, and extracts the drawable graph via `getGraph()` and Mermaid via `drawMermaid()`

### Format Bridging

The extension bridges two trace formats transparently:

| SDK Phase    | Legacy StepType | LangGraph Node |
|--------------|-----------------|----------------|
| `reason`     | `llm`           | `llm`          |
| `tool`       | `tool`          | `tool_<name>`  |
| `observe`    | `llm`           | `llm`          |
| `memory`     | `state`         | `state`        |
| `retry`      | `error`         | `error`        |
| `terminate`  | `end`           | `__end__`      |

## Development

```bash
cd vscode-extension
npm install
npm run compile    # or npm run watch
```

Press `F5` in VS Code to launch the Extension Development Host.

## Dependencies

- `@langchain/langgraph` ^1.2.0 - StateGraph compilation and Mermaid generation
- `@langchain/core` ^1.1.29 - Required by langgraph
- VS Code ^1.85.0
